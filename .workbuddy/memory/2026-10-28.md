## 双击脚本编码问题修复（根因定位 + 解决）
- **现象**：用户双击 `测试weed.bat` 报一堆零散错误（`'ho' 不是内部或外部命令`、`'Start-Process' 不是...`、`'9333"' 不是...`、`'舳?weed'`、`'mand'`/`'ndstr'` 命令关键字丢头字符等）。
- **根因（两重）**：
  1. `.bat` 文件被工具写成 **UTF-8 无 BOM**，而 cmd 双击用系统默认 GBK(936) 代码页解读 → 中文注释字节乱码，乱码字节被误判为换行/引号，把整行命令切碎。
  2. 即使改 GBK，若换行符是 **LF(\n) 而非 CRLF(\r\n)**，cmd 解析含中文双字节的 `.bat` 会吞掉下一行命令开头的字符（`command`→`mand`、`findstr`→`ndstr`）。
- **正确做法**：`.bat` 必须 **GBK 编码 + CRLF 换行**，且提示文字尽量用英文避开中文编码雷区；`.ps1` 必须 **UTF-8 带 BOM**（PowerShell 5.1 识别非 ASCII 需要 BOM）。
- **编写方式**：不能直接用 Write 工具（会写 UTF-8+LF），需用 `awk '{printf "%s\r\n",$0}' | iconv -f UTF-8 -t GBK` 转码；或 PowerShell 用 `[Text.Encoding]::GetEncoding(936)` + `` `r`n `` join 写字节。
- **weed 启动诊断结论**：weed.exe 本身完全正常。`start /min` 前台启动下，master(19333)/filer(8888)/volume(18080)/S3(8333) 四端口全部 LISTENING，leader 选举成功后所有组件自愈（日志里 `Not current leader`、`connection refused` 是启动期并行初始化的正常现象，非错误）。
- **脚本改造**：start-reader.ps1 里启动 weed 从 `Start-Process weed.exe` 改为 `Start-Process cmd.exe /c start "weed" /min ...`（`start /min` 在真实双击环境更稳）；两个 `.bat` 入口转 CRLF；`get-url.ps1`/`start-reader.ps1` 保持 UTF-8 BOM。
- **注意**：WorkBuddy 沙箱会在每次工具调用间清理派生子进程，所以沙箱内跑 start-reader.ps1 后端口很快空，但日志（backend.log/cloudflared.log）证明组件真实启动成功，不影响用户真实双击。
