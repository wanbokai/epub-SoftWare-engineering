## 公网访问（Cloudflare Quick Tunnel）
- 需求：用户想手机/平板 + 给他人演示，不想买服务器、不想备案，可保持电脑开机。
- 方案：cloudflared Quick Tunnel（无需域名、无需登录授权，一条命令生成公网 HTTPS 链接）。
- 安装：用户用 winget 安装 `Cloudflare.cloudflared`（winget v1.29.380 可用）。
- 命令：`cloudflared tunnel --url http://localhost:8080`。
- 坑：`cloudflared tunnel login` 会卡在授权页（账户无 zone/域名时列表为空、无 Authorize 按钮），改用 Quick Tunnel 直接跳过。
- 公网链接：https://measured-llp-pipeline-optics.trycloudflare.com（每次重启 cloudflared 会变）。
- 验证：公网首页/静态资源/SPA路由/health 全 200；注册、登录均 200，完整链路打通。
- 注意：Quick Tunnel 无 uptime 保证、仅限试用；生产需用 named tunnel。电脑须保持开机，链接才会生效。

- **踩坑 1（中文路径）**：原目录名含「阅读器」，PowerShell 5.1 读脚本乱码 + Start-Process 传中文路径给 Java 乱码。已通过改英文目录解决。
- **踩坑 2（代理环境变量冲突）**：环境里同时有 HTTP_PROXY/http_proxy 等大小写变体（WorkBuddy 会话注入的 49704 代理），Windows 环境变量不区分大小写，导致 PowerShell 5.1 的 Start-Process 给子进程准备环境时抛「已添加具有相同键的项」异常。已在 start-reader.ps1 开头用 `[Environment]::SetEnvironmentVariable($k,$null,"Process")` 清理小写变体解决。

- **注意**：通过 WorkBuddy 沙箱测试时，PowerShell 的 Start-Process 启动外部 exe 会被沙箱拦截（报「操作已被用户取消」），但真正开机自启由 Windows 直接执行 bat，不受此限制，脚本逻辑本身正确。
