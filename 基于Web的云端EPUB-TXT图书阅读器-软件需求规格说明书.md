## 1. 引言

### 1.1 编写目的

本文档是软件工程课程项目《基于 Web 的云端 EPUB/TXT 图书阅读器》的需求分析产物，参照 GB/T 8567-2006 与 IEEE Std 830 的编制框架撰写，旨在完整、准确地定义系统的功能需求、数据需求与非功能性需求，作为后续概要设计、详细设计、编码实现与验收测试的基准依据。预期读者为课程小组成员、指导教师以及后续参与开发与测试的同学。

### 1.2 项目背景与业务范围

**项目背景**：电子书阅读需求日益普遍，但现有桌面阅读器需要安装客户端、阅读进度难以跨设备衔接，且对 EPUB/TXT 两种最常见的纯文本电子书格式缺乏统一的云端管理体验。本项目拟开发一个打开浏览器即可使用的云端阅读器：用户导入自有电子书后，可在任意设备上继续阅读，阅读进度与排版配置自动多端同步。

**业务范围（In Scope）**：

- 用户注册登录与 JWT 鉴权；
- EPUB/TXT 文件的上传导入、格式校验与解析；
- 云书架的展示、检索、排序与移除；
- 在线阅读核心引擎（分页/流式渲染、多级目录导航）；
- 阅读视觉主题与排版参数设置；
- 阅读进度与排版配置的多端云同步及冲突消解。

**非目标（Out of Scope）**：在线书城与付费交易、DRM 版权保护、社交批注与分享、EPUB 3 音视频交互资源、原生移动 App。以上内容不在本课程项目范围内。

## 2. 总体描述

### 2.1 产品愿景与系统架构概述

**产品愿景**：一次导入，处处可读——打开浏览器，就能从上次的位置继续阅读。

**系统架构概述**：系统采用 B/S 架构、前后端分离的三层结构：

1. **浏览器端（SPA 前端）**：采用 **Vue 3 + TypeScript** 构建的阅读核心引擎（渲染、分页、目录导航）、书架与设置界面、本地缓存层（IndexedDB：书籍资源缓存、进度副本、配置副本）、后台解析单元（Web Worker）；
2. **应用服务层（RESTful API）**：采用 **Java + Spring Boot 3** 构建，包含账号与 JWT 鉴权服务（Spring Security）、文件接收与秒传预检服务、书架 CRUD 服务、进度与配置同步服务（含冲突检测）；数据访问通过 **MyBatis** 参数化映射实现；
3. **数据层**：关系型数据库 MySQL 8.0（用户、书架条目、排版配置等业务数据）+ 对象存储（物理图书文件，按 SHA-256 内容寻址去重存储）。

前后端通过 HTTPS + RESTful JSON API 交互；未登录时前端可独立运行于"本地模式"，数据仅存 IndexedDB。

### 2.2 用户角色与特征

| 角色    | 特征与权限                                                                               |
| ----- | ----------------------------------------------------------------------------------- |
| 未认证访客 | 未注册/未登录用户。可注册账号（UC-01）；可在本地模式下导入并阅读图书（UC-04～06、UC-07～12），数据仅存本机 IndexedDB，不上云、不参与同步 |
| 注册读者  | 已登录用户。拥有访客全部能力，另可使用云书架、云端文件存储与秒传、多端进度与配置同步、冲突消解等完整功能（UC-02、UC-03）                   |

用户总体特征：具备基本浏览器使用能力的普通读者而非技术专家；阅读设备可能是 PC、平板或手机，横竖屏不定，因此系统须提供响应式布局与触屏手势支持。

### 2.3 运行环境约束

- **客户端**：现代桌面/移动浏览器（Chrome、Edge、Firefox、Safari 的最近两个主要版本），要求支持 IndexedDB、Web Worker、Fetch API；桌面建议分辨率不低于 1280×720，移动端响应式适配；
- **服务端**：Linux 服务器，Nginx 反向代理，全程 HTTPS；应用服务实现技术栈为 **Java 17 + Spring Boot 3 + MyBatis**，构建工具 Maven；
- **数据环境**：MySQL 8.0（或同级关系数据库）+ MinIO/SeaweedFS 或云对象存储；单文件上传上限 100 MB。

### 2.4 假设与依赖

- 假设 1：用户导入的图书为其自有的合法电子书文件，系统不承担内容合规审查责任；
- 假设 2：用户浏览器环境现代且 JavaScript 可用；网络总体连通，离线属短暂异常而非常态；
- 依赖 1：浏览器 IndexedDB 与 Web Worker 能力（离线降级与解析性能依赖于此）；
- 依赖 2：EPUB 解析组件（前端 epub.js 等第三方库 / 后端 Java epublib 或自研解析）对 EPUB 2/3 规范子集的解析支持；
- 依赖 3：对象存储服务的可用性与数据冗余能力。

### 3.2 模块一：用户登录与云端同步模块

#### 3.2.1 UC-01 账号注册与 JWT 鉴权用例

| 项目   | 内容                                                                                                                                                                                  |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 需求编号 | FR-01                                                                                                                                                                               |
| 参与者  | 未认证访客                                                                                                                                                                               |
| 前置条件 | 系统可访问，用户处于未登录状态                                                                                                                                                                     |
| 基本流  | 1. 访客在登录页选择"注册"，输入用户名、邮箱与密码（不少于 8 位且含字母与数字）；2. 前端校验通过后提交，服务端校验用户名与邮箱唯一性；3. 服务端以 BCrypt（cost ≥ 10）哈希密码后写入用户表；4. 注册成功，签发 JWT（有效期 2 小时）与 Refresh Token（14 天）；5. 前端将令牌存入安全存储，自动登录并进入云书架 |
| 备选流  | 2a. 用户名或邮箱已存在：提示后返回重新填写；1a. 密码强度不足：前端即时提示，不提交                                                                                                                                       |
| 异常流  | 3a. 服务端写入异常：整体回滚，返回错误信息，不产生半写数据                                                                                                                                                     |
| 后置条件 | 用户记录创建成功，客户端持有有效令牌，后续请求携带 JWT 鉴权                                                                                                                                                    |

#### 3.2.2 UC-02 阅读进度与排版配置的多端云同步用例

| 项目   | 内容                                                                                                                                                    |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| 需求编号 | FR-02                                                                                                                                                 |
| 参与者  | 注册读者                                                                                                                                                  |
| 前置条件 | 读者已登录，且至少一端产生过阅读或排版变更                                                                                                                                 |
| 基本流  | 1. 阅读或修改排版时，前端按节流策略（翻页 5 次或间隔 30 秒）触发同步请求，携带书架条目 ID、进度 CFI、配置内容及 sync_version；2. 服务端校验 JWT 与数据归属；3. 版本号一致则写入云端并递增版本号；4. 其他设备打开书架或阅读器时拉取最新进度与配置并更新本地副本 |
| 备选流  | 4a. 用户在设置中可关闭自动同步，改为进入书架时手动拉取                                                                                                                         |
| 异常流  | 2a. 网络失败：变更写入本地 IndexedDB 队列并标记 dirty，网络恢复后自动补传                                                                                                       |
| 后置条件 | 云端进度与配置为该账号当前最新一致状态，多端可见                                                                                                                              |

#### 3.2.3 UC-03 多端进度冲突检测与消解用例

| 项目   | 内容                                                                                                                                                                |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 需求编号 | FR-03                                                                                                                                                             |
| 参与者  | 注册读者                                                                                                                                                              |
| 前置条件 | 同一账号在两台及以上设备离线期间各自产生了进度变更                                                                                                                                         |
| 基本流  | 1. 某端恢复网络后上传进度，携带本地 sync_version；2. 服务端比对发现本地版本落后于云端版本，判定为冲突；3. 返回冲突响应，包含云端与本端进度的时间戳、章节及位置摘要；4. 前端弹出消解面板，供用户选择"保留云端 / 采用本机 / 按最后阅读时间自动（LWW）"；5. 按用户选择写入云端并统一两端版本号 |
| 备选流  | 4a. 用户未在 60 秒内选择：默认按 LWW 策略自动消解并告知结果                                                                                                                              |
| 异常流  | 5a. 消解写入失败：保持云端版本，本端数据留在 dirty 队列待重试                                                                                                                              |
| 后置条件 | 多端进度重新一致，版本号收敛，冲突记录可追溯                                                                                                                                            |

### 3.3 模块二：图书导入与解析模块

#### 3.3.1 UC-04 文件格式校验与 SHA-256 秒传预检用例

| 项目   | 内容                                                                                                                                                                                                                 |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 需求编号 | FR-04                                                                                                                                                                                                              |
| 参与者  | 未认证访客（本机导入）/ 注册读者（云端导入）                                                                                                                                                                                            |
| 前置条件 | 用户点击"导入图书"按钮                                                                                                                                                                                                       |
| 基本流  | 1. 用户选择 .epub 或 .txt 文件（不超过 100 MB）；2. 前端校验扩展名与文件头魔数（EPUB 为 ZIP 头"PK"，TXT 校验字节流可解码）；3. Web Worker 计算文件 SHA-256 指纹；4. 云端模式下先发起秒传预检：该指纹已存在于物理文件资源表时，服务端仅新建书架条目并引用既有物理文件，跳过上传，提示"秒传成功"；5. 指纹不存在则执行分片上传至对象存储，并登记物理文件资源 |
| 备选流  | 4a. 秒传预检接口异常：自动降级为完整分片上传；5a. 分片上传中断：支持断点续传，从已完成分片继续                                                                                                                                                                |
| 异常流  | 2a. 格式或魔数不符：拒绝导入，提示仅支持 EPUB/TXT；2b. 超过大小上限：拒绝并提示上限                                                                                                                                                                 |
| 后置条件 | 书架新增该图书条目；同一物理文件在存储端按 SHA-256 全局唯一                                                                                                                                                                                 |

#### 3.3.2 UC-05 TXT 字符编码识别与正则自动分章用例

| 项目   | 内容                                                                                                                                                                                                                       |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 需求编号 | FR-05                                                                                                                                                                                                                    |
| 参与者  | 未认证访客（本机）/ 注册读者（云端）                                                                                                                                                                                                      |
| 前置条件 | 已导入合法 TXT 文件                                                                                                                                                                                                             |
| 基本流  | 1. Web Worker 读取文件头字节，按"BOM 标记 → UTF-8 合法性校验 → GB18030 → UTF-16"的顺序识别编码，解码为统一文本流；2. 按内置正则模式（如"第[一二三四五六七八九十百千0-9]+[章节卷回]"、"Chapter N"、数字序号行等）匹配章节标题行；3. 命中不少于 3 处则生成分章目录，未命中则按固定长度切分为伪章节并提示；4. 生成带目录的标准内部章节数据并入库（或写入本地缓存） |
| 备选流  | 3a. 用户可在设置中切换正则模式并重新分章；1a. 编码识别置信度低：弹窗供用户手动选择编码后重试                                                                                                                                                                       |
| 异常流  | 1b. 全部编码尝试均失败：提示"无法识别的文本编码"并终止导入                                                                                                                                                                                         |
| 后置条件 | TXT 转换为带目录结构的标准内部书对象，可进入阅读                                                                                                                                                                                               |

#### 3.3.3 UC-06 EPUB 解压、元数据及目录结构解析用例

| 项目   | 内容                                                                                                                                                                                 |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 需求编号 | FR-06                                                                                                                                                                              |
| 参与者  | 未认证访客（本机）/ 注册读者（云端）                                                                                                                                                                |
| 前置条件 | 已导入合法 EPUB 文件                                                                                                                                                                      |
| 基本流  | 1. Web Worker 在前端解压 ZIP 容器；2. 读取 META-INF/container.xml 定位 OPF 包文件；3. 解析 OPF 提取元数据（书名、作者、封面图）与 spine（阅读顺序）；4. 解析 NCX（EPUB2）/ NAV（EPUB3）生成多级目录树；5. 规范化内部资源路径，组装为标准内部书对象后入库（或写入本地缓存） |
| 备选流  | 4a. 无目录文件：按 spine 顺序自动生成单级目录                                                                                                                                                       |
| 异常流  | 1a. ZIP 容器损坏或 OPF 缺失：提示"文件已损坏"，提供降级为纯文本方式打开的选项                                                                                                                                     |
| 后置条件 | EPUB 转换为含元数据、spine 顺序与多级目录的标准内部书对象                                                                                                                                                 |

### 3.4 模块三：书架管理模块

#### 3.4.1 UC-07 云书架列表展示与视图切换用例

| 项目   | 内容                                                                                                                          |
| ---- | --------------------------------------------------------------------------------------------------------------------------- |
| 需求编号 | FR-07                                                                                                                       |
| 参与者  | 注册读者（访客为本机书架，逻辑相同）                                                                                                          |
| 前置条件 | 用户进入书架页                                                                                                                     |

## 4. 数据需求与概念模型

### 4.1 概念数据模型（E-R 图）

系统包含四个核心实体：用户、物理文件资源、用户书架条目、排版配置。概念模型如图 4-1（结构化文本表示）：

```text
┌────────┐  1        N  ┌──────────────┐  N        1  ┌──────────────┐
│  用户  │─────拥有─────│   书架条目    │─────引用─────│ 物理文件资源  │
└────────┘              └──────────────┘              └──────────────┘
    │ 1                       │
    │                         │ 含属性：进度 CFI、进度百分比、最近阅读时间
    ▼ 1
┌──────────────┐
│   排版配置    │
└──────────────┘
```

联系说明：

- **用户 — 书架条目**：1 : N，一个用户可拥有多条书架条目；
- **书架条目 — 物理文件资源**：N : 1，同一物理文件可被多个用户的书架条目引用（支撑秒传去重），物理文件全局按 SHA-256 唯一；
- **用户 — 排版配置**：1 : 1，阅读配置全局唯一；
- **阅读进度**不单独建实体，作为书架条目的属性（CFI 锚点 + 百分比 + 最近阅读时间）存储。

### 4.3 本地缓存（IndexedDB）与云端数据同步协议说明

**本地缓存结构（IndexedDB）**：

- **book_cache**：已打开图书的解压后资源（章节数据、样式、图片），支撑离线继续阅读与二次打开加速；
- **local_bookshelf**：云端书架的本地副本，含各条目 dirty 标记；
- **local_config**：排版配置本地副本及待同步队列。

**同步协议（版本号 + LWW + 冲突交互消解）**：

1. 每条同步数据（进度、配置）携带单调递增的 sync_version，作为一致性判定依据；
2. **上行**：本地 dirty 数据按节流窗口批量 push；服务端比对版本号，一致则写入并递增；本地落后则返回冲突响应，转入 UC-03 消解流程；
3. **下行**：登录成功、进入书架、打开阅读器三个时机触发增量 pull，并写入本地副本；
4. **离线补偿**：离线期间的变更按发生顺序进入本地队列，网络恢复后依序重放（同第 2 步）；
5. **物理文件**不参与双向同步，仅按需从对象存储拉取并缓存至 IndexedDB，秒传命中时完全不传输文件体。

## 5. 非功能性需求

### 5.1 性能需求

| 指标项                | 目标值                    |
| ------------------ | ---------------------- |
| 书架首屏渲染（缓存命中）       | ≤ 1 s                  |
| 云端同步接口响应时间         | P95 ≤ 500 ms           |
| 20 MB EPUB 解析并打开首章 | ≤ 3 s（Web Worker 后台解析） |
| 5 MB TXT 解码与自动分章   | ≤ 2 s                  |
| 大文件解析期间主线程阻塞       | < 100 ms，UI 保持可响应      |
| 单次翻页/重排体感延迟        | ≤ 100 ms               |

### 5.2 安全性需求

- **密码安全**：密码一律 BCrypt（cost ≥ 10）哈希存储，禁止明文或可逆加密，禁止日志打印密码；
- **传输安全**：全站 HTTPS（TLS ≥ 1.2），禁止明文 HTTP 通信；
- **鉴权与越权防御**：JWT 短期有效（2 小时）配合 Refresh Token 轮换；所有接口校验资源归属，访问他人书架条目或文件一律拒绝（403/404），防水平越权；
- **XSS 防御**：EPUB/TXT 正文渲染于沙箱化 iframe（sandbox 属性禁用脚本），后端对元数据等注入点输出转义；
- **注入防御**：SQL 一律参数化预编译；
- **上传安全**：扩展名 + 魔数双重白名单校验、100 MB 大小上限、存储文件名随机化、禁止可执行文件。

### 5.3 可靠性与容错性需求

- **弱网离线降级**：断网时自动切换本地模式，已缓存图书可继续阅读，进度变更入队待同步（见 4.3）；
- **异常格式恢复**：EPUB 容器损坏时提示并提供纯文本降级渲染；编码识别失败时允许手动指定编码重试，不导致会话崩溃；
- **断点续传**：大文件分片上传，中断后从已完成分片继续；配合 SHA-256 秒传避免重复流量；
- **数据可靠性**：数据库每日备份，对象存储冗余存储；IndexedDB 写入失败（如空间不足）时明确提示用户。

### 5.4 兼容性需求

- **浏览器**：Chrome、Edge、Firefox、Safari 最近两个主要版本全功能可用；明确不支持 IE 等传统浏览器；
- **设备**：桌面端（≥ 1280px）与移动端浏览器响应式适配，触屏手势可用；
- **文件格式**：EPUB 2.x / 3.x 基本渲染；TXT 支持 UTF-8、UTF-16、GBK、GB18030 编码；
- **显示环境**：深浅色系统模式均可正确展示（见 UC-11）。
